section 03

what are key areas where analytics engineers add value?

analytics engineers obsess over these questions

what context (documentation) do we need to provide about the model, so business users can use it quickly?

how should tables be modelled so they are cost-optimal?

what is the clearest possible naming convention for tables and columns in our warehouse?

how can we be notified of a problem in the data before a business user finds a broken chart in our visualisation tool?

how can we ensure and improve the quality of our data as it's produced, rather than cleaning it downstream?

how do we set guardrails to allow others to develop their own models?

where do we set access controls to protect data privacy and ensure regulatory compliance?

how should projects be structured for good cross-domain collaboration and scalability?

well-modelled data enables faster data mining cycles

the analytics engineer takes on much of the first steps when modelling (structuring) the datasets. if done right, there is a significantly reduced workload when performing data mining, as the datasets used are:

  • contextualised (ease of business understanding)
  • easily discoverable (facilitates data understanding)
  • reliable (good data quality; less data preparation, such as cleaning and formatting)
