how are dbt projects structured?

    models are the basic building blocks. one model has one file, and contains logic that either transforms raw data into a dataset that is ready for analytics, or an intermediate step.

    docs: documentation can be written in markdown files.

    tests: you can write tests in SQL to test models.

    .github/workflows: workflows are executed as part of the CI/CD pipeline.

    packages.yml: configuration to take modularised code from libraries.

      ~3.2×

      storage is cheaper than compute

      • if you scan large amounts of data frequently, query cost dominates.
      • so to optimise, you would prefer storage over compute.

      example, with Google Cloud

      storage: €17.408 per TiB per month
      query compute: €5.44 per TiB processed

      breakeven: 17.408 / 5.44 ≈ 3.2 TiB processed per month per TiB stored.

      • if you query more than ~3.2× the stored data per month, storage is cheaper.
      • after about 3.2 full scans a month, the query cost overtakes the storage cost.
